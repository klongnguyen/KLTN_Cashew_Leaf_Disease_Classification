# EXP-RESNET50-YOLO-PIPELINE-033

Notebook: `cashew_resnet50_yolo_pipeline_033.ipynb`. Run its cells in order in a fresh Colab GPU runtime. Part A evaluates the frozen ResNet50 032 prediction bundle. Part B retrains the ResNet50 032 ImageNet transfer recipe for five seeds and exports a standalone ResNet50 + YOLO26s pipeline. Set `EXP033_DRY_RUN=1` only for a synthetic logic check; its scores are not experimental results.

The user chose ResNet50 032 instead of 031 because Stage 2 was more stable. This was a user decision after Test/Holdout had been viewed, **not** the locked `val_loss` selection rule; ResNet50 031 has lower `val_loss`. Holdout 09 has four classes and 126 images and is a descriptive audit, not a blind benchmark. F2 is post hoc. No Holdout result selects a threshold, model, stacker, or default rule.

The notebook uses the same Split 13, Holdout 09, YOLO26s weights and detector inputs, leakage checks, clean Validation rule, BOX_CONF selection on YOLO Validation, fusion rules F0–F3b, GroupKFold stacker search, bootstrap, Wilson intervals, and error taxonomy as the DenseNet121 + YOLO 032 pipeline. The detector is not retrained. TAU is selected again on ResNet50 clean Validation by the EXP-031 Youden J procedure with a sensitivity floor of 0.85 and a Validation cost ceiling of 2 percentage points. The `tau_selection.json` output records the value; 0.60 is only the DenseNet reference.

Part A embeds 15 original `predictions_standard.csv` files from the ResNet50 032 ANALYSIS ZIP with source SHA256 `0d3d339438726cf03867b5f02ea781dc64946919238ed28a1e8307883be6d6bd`. Their member hashes are verified at runtime. Test and Holdout probabilities remain unopened until the Validation fusion config is written. The five probabilities, dataset hash, seed and image key are checked against the inventory. The notebook recalculates F0 independently from the source CSVs.

Part B uses the `conv5_block3` prefix, Stage 2 learning rate `5e-6`, frozen BatchNorm, Caffe BGR preprocessing and the ResNet50 032 checkpoint selection rule. The exported Python module registers both custom Keras layers. The notebook checks the complete five-model + YOLO pipeline in its main process, then reloads one exported Keras model in a fresh CPU process to verify serialization without duplicating the whole pipeline in Colab memory. A fresh-process failure writes `fresh_process_reload.json` with the last stage and native error output. `RUN_PART_A_031_SENSITIVITY` is disabled by default; enable it only with a local ResNet50 031 ANALYSIS ZIP whose SHA256 matches the configured pin. The separate result table is labelled exploratory.

Final output includes separate Part A and Part B tables, per-image/seed/rule predictions, comparison with F0, optional comparison with DenseNet121 + YOLO 032 when its result ZIP is supplied, analysis and artifact manifests, latency, and ANALYSIS/FULL ZIPs. A missing DenseNet reference is shown as unavailable, not filled with an estimate. Each per-seed recovery ZIP contains the fixed Validation checkpoint snapshot; later Test/Holdout prediction CSVs do not change it during a rerun. With `RESTORE_EXISTING_SEEDS_FROM_DRIVE=True`, a fresh Colab runtime verifies the existing ZIP's Drive MD5, ZIP CRC and model SHA256, then restores it before training. If a different local seed was already trained under this experiment ID, the notebook preserves it in `EXP-RESNET50-YOLO-PIPELINE-033_local_conflicts` and resumes from the archived seed. The notebook verifies ZIP integrity and checks Drive MD5 after upload to folder `1DGKTnzsvVc60RIEn5lQgflR3s-loM24G`.
